# 知识与经验量化系统

> 把一个人的**知识、经验、判断方式、行为特征**量化成一份可长期累积的能力档案，
> 让 AI 每次回答都贴合你的真实水平，而不是给一份通用答案。

这不是资料仓库，也不是笔记软件。它回答的是四个问题：

| 问题 | 对应轨道 | 会过期吗 |
|---|---|---|
| 我知道什么 | A 知识图谱 | **会**，按学科差异化衰减 |
| 我做过什么、怎么做 | B 经验档案 | 不会 → 提炼为 Playbook |
| 我怎么判断 | C 智慧原则 | 几乎不 |
| 我是什么样的人 / 卡在哪 | D 行为画像 / E 问题日志 | 缓慢修正 / 零成本累积 |

底层是一套 **append-only 的证据流水**：分数不是写死的，而是由证据算出来的，
任何时刻可审计、可回滚。所以档案既能升（学了新东西），也能降（真的生疏了）——
「生疏了」这个状态，恰恰是这套系统最有价值的地方。

## 快速开始

### 方式一：整仓库部署（推荐）

```bash
git clone https://github.com/spelatm/bulid-your-knowledge-life.git
cd bulid-your-knowledge-life
python3 scripts/bootstrap.py --check --user default
```

把整个目录放进你的智能体的 skill 目录（例如 `~/.workbuddy/skills/knowledge-profile/`），
之后智能体读到 `SKILL.md` 就会自动进入这套流程。无需安装依赖，只用标准库。

### 方式二：不要脚本

**把 `SKILL.md` + `references/` 复制过去就行**，不需要 `scripts/`。
`references/manual-mode.md` §0.8 定义了「没有脚本时怎么做」的手工口径——
智能体自己建目录、自己算分、自己落盘，算法与整仓库版完全一致。

### 方式三：只留一个文件

**只复制 `SKILL.md`** 也能勉强跑。主文档末尾的「最小闭环」内联了算分公式、
状态区间、衰减档位和最小存储要求，够跑通「建档 → 提问 → 录入」这条主线，
精度略低。

> 同一份规则，三种部署形态：
> **A 完整仓库**（有 `scripts/` + `references/`）以脚本为准；
> **A− 纯文档**（有 `references/`，无 `scripts/`）走手工口径；
> **B 单文件**（只有 `SKILL.md`）走最小闭环。
> A 形态下 Python 不可用或脚本报错，会自动降级到 A−。

### 为什么主文档这么短

`SKILL.md` 是**索引式主文档**（约 340 行），只装四样东西：
一张常用词表、五条不可协商的约束、怎么判断当前环境、以及遇到情况查哪份文档。
具体动作拆成七份子文档放在 `references/`，正在做哪件事就读哪一份：

| 子文档 | 管什么 | 行数 |
|---|---|---|
| `onboarding.md` | 建档、采集背景的话术、冷启动推断 | 173 |
| `answering.md` | 回答一个问题的七步流程、报告八节、说话的分寸 | 150 |
| `recording.md` | 证据怎么录、经验/原则/特征怎么记、横向边、技能 | 220 |
| `expansion.md` | 静态模板覆盖不了，去网上查了补进档案 | 83 |
| `manual-mode.md` | 没有脚本时的全套手工做法 + 完整仓库地图 | 207 |
| `model.md` | 分数怎么算、字段填什么、想调参数改哪 | 177 |
| `improving.md` | 改系统的五步流程、脚本清单、自检清单、禁区 | 202 |

拆之前是一份 1063 行的文档——智能体要么读不完，要么读完了记不住。
拆之后每次只加载主文档，需要细节时再取那一份。

**写法上的一个约定**：这份文档首先是给智能体执行的，所以主体是表格和命令；
但用户可以随时查阅，所以每条规则都写成能独立看懂的一句话——
术语在 `SKILL.md` 开头有一张表解释一遍，后面直接用，不重复解释、也不展开成论述。

## 智能体读到文档后会做什么

1. **认领角色** —— 五条不变量立即生效（见下）
2. **探测部署形态** —— A 完整仓库 / A− 纯文档 / B 单文件
3. **判定档案状态** —— `new` / `partial` / `ready`，然后按状态分路：
   - `new` → 采集学历 / 职业 / 区域三项背景（一次问清）
   - `partial` → 只补缺的那几项
   - `ready` → 直接进入正常流程，**永不再问背景**

此后每次提问，它都会先查档案、按你的掌握程度决定讲多深，
再把这次对话产生的新证据写回档案。

## 五条不变量

违反任一条即视为执行失败：

| # | 不变量 |
|---|---|
| I1 | **先查档案，再开口** |
| I2 | **无证据不写分**：推断必须标记为未确认，且不得当作"你已掌握"来讲 |
| I3 | **证据只追加**：撤销 = 追加反向证据，永不删除原记录 |
| I4 | **改系统先确认**：验证 → 确认 → 才改，不先动手 |
| I5 | **不评判、不夸大**：不说"你很弱"，说"这块的证据还比较少" |

## 目录结构

```
knowledge-profile/
├─ SKILL.md              主文档：角色 / 不变量 / 模式探测 / 场景路由表（~250 行）
├─ references/           子文档：按会话阶段拆，用到才读（7 份）
├─ CHANGELOG.md          系统变更记录
├─ _meta/                配置层：权重、衰减、等级、域与切面、字段定义
├─ graph/                预置学科骨架（9 个学科，只装"能被某门课教"的东西）
├─ skills/               预置技能簇（按能力簇组织，不按学科）
├─ inference/            背景推断模板：学历 / 职业 / 区域
├─ templates/            各轨录入模板 + 7 个流程类 Playbook 模板
├─ scripts/              可执行脚本（标准库实现）
├─ design/               设计草案与迁移记录
├─ archive/              仅存 git 表达不了的资产
└─ users/<user_id>/      每个用户隔离的五轨档案
```

配置与代码分离：**改数值不用改代码**。权重在 `_meta/weights.md`，
半衰期在 `_meta/decay_profiles.md`，学科骨架在 `graph/`，技能簇在 `skills/`，
域与切面规则在 `_meta/domains.md`，推断规则在 `inference/`。

## 三个容易混的边界

| | 知识 | 技能 | 经验 |
|---|---|---|---|
| 回答 | 是什么 | 会不会做 | 在什么情况下怎么做 |
| 组织轴 | 学科树 | 能力簇 | 情境 |
| 分数来源 | 学习证据 | 行为证据 | 不打分，只记事实 |
| 落点 | `points/` | `experience/skills/` | `experience/` |
| 会过期吗 | 会（45–365 天） | 慢（730 天） | 不会 |

**两套分数互不推导**，相减得到一个这套系统独有的指标：

```
gap = 技能熟练度 − 支撑它的知识点均分
```

`+20` 以上＝手熟但原理淡了（该补原理）；`−20` 以下＝学过但没做过（该给练习）。
简历只能回答「你做过什么」，回答不了这个错位——而它恰恰决定该补课还是该练手。

知识点之间还有一层**横向边**：你在同一个场景里同时用到 A 和 B，就算一次「共现」；
共现够了系统才会建议「这两条要连吗」。纵向边是学科给的，**横向边是你自己长出来的**。

## 量化口径

```
正向累积（边际递减）   raw += (100 - raw) × w/100 × confidence
负向证据               raw ×= 系数（forgot 0.85 / selftest_fail 0.92 / rusty_asked 0.90）
时间衰减               current = raw × 0.5^(Δt / 半衰期)
```

证据强度从强到弱：主导项目 > 教别人 / 写文章 > 有产出佐证 > 通过自测 >
系统学习 > 用户自评 > **背景推断**（权重刻意最低，不让它污染真实分数）。

状态位：`未触及 → 听说过 → 理解原理 → 能上手做 → 精通`，外加 `生疏了`。

## 这套系统不做什么

- ❌ 不保存资料原文。只记"你知道什么"，不记"网上写了什么"
- ❌ 不推断敏感属性（健康、政治立场、宗教、性取向等）；地域只推产业环境
- ❌ **没有来源的推断不入库**——不可追溯的推断等于编造
- ❌ 不逐条追问推断结果，一律批量轻量告知
- ❌ 不为了维护档案而拖慢回答：查询或写入失败不阻塞对话
