# 学科衰减档位表

> 半衰期 = 掌握度衰减到一半所需天数。按学科差异化配置。

## 档位定义

| 档位 | 半衰期 | 适用知识类型 | 理由 |
|---|---:|---|---|
| `volatile` | 45 天 | 词汇、外语、API 细节、版本号、具体参数 | 纯记忆，掉得最快 |
| `tooling` | 90 天 | 工具、框架、软件操作、命令行 | 不用就忘，且版本会变 |
| `foundation` | 180 天 | 数理基础、核心概念、专业基本功 | 理解了就不太会忘 |
| `methodology` | 365 天 | 方法论、思维方式、设计原则 | 一旦内化基本不掉 |
| `durable` | 730 天 | **技能**（`experience/skills/`：与人沟通、动手做、带人） | 会生疏，但不会忘掉「会」 |
| `permanent` | ∞ | 母语、常识、基本生活技能 | 不参与衰减计算 |

> `durable` 专给技能用：技能与知识的衰减机制不同——知识会**忘**，
> 技能只会**钝**。两年半衰期是刻意的粗估，宁可迟钝也不要让
> 「十年前会开车」在档案里归零。

## 档位从哪来（3.8.0 起）

**档位写在课程索引的 frontmatter 里**：`graph/<门类>/<学科>/<课程>.md` 的 `profile:`。
一个课程一个档位，不再按学科一律给一个默认值——同一学科里「理论」和「工具」本来就不同寿命。

```yaml
# graph/人文与艺术/外国语言文学/词汇.md
---
category: 人文与艺术
subject: 外国语言文学
course: 词汇
profile: volatile        # ← 这一门课掉得最快
---
```

单个知识点要覆盖时，在条目行后加 `〔tooling〕`：

```markdown
- 短语动词 ⭐⭐〔tooling〕
```

优先级：**条目内联 `〔档位〕` > 课程索引 `profile:` > 全局默认（90 天）**；
用户档案里某条知识点的 `profile` 字段可以再覆盖一次。

### 谁用哪个档（判断依据）

| 知识类型 | 档位 | 理由 |
|---|---|---|
| 词汇、语法点、条文、具体参数 | `volatile` | 纯记忆，掉得最快；条文还会修订 |
| 工具、框架、软件操作、历史事实 | `tooling` | 不用就忘，且版本会变 |
| 数理基础、核心概念、专业基本功 | `foundation` | 理解了就不太会忘 |
| 方法论、思维方式、设计原则、管理理论 | `methodology` | 一旦内化基本不掉 |
| **技能实体**（`experience/skills/`） | `durable` | 技能不用学科映射，统一档位 |
| 母语、常识 | `permanent` | 不衰减 |

现有的具体分配（37 个学科里哪些课程偏离 `foundation`）见
`scripts/migrate_g1.py` 的 `PROFILE` 表——那是**唯一权威**，
本节只讲判断依据，不再抄一份完整清单（抄件必漂）。

> **一处历史缺陷（3.8.0 修的）**：旧 `parse_graph` 只在 `# 学科名` 那一行找反引号，
> 而档位写在第三行的说明句里，于是所有学科的默认值都退化成 `foundation`。
> 外语（本该 `volatile`）、商业与管理（本该 `methodology`）、
> 人文社科与艺术（部分 `methodology`）全部算错。骨架已按新表重建；
> **已有用户档案里的 `profile` 字段没有回填**——那会改变衰减结果，
> 是独立决策，见 `CHANGELOG` 3.8.0「未做」。

## 计算

```
current_score = raw_score × 0.5^(Δt / half_life)
Δt = 今天 - last_verified_at
```

`permanent` 档位：`current_score = raw_score`，不衰减。

## 生疏判定

```
current ≤ peak × 0.6  且  peak ≥ 40   →  status = rusty
```

rusty 不是"不会"，而是"曾经会、现在可能废了"——全系统最有价值的状态位。
