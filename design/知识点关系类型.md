# 知识点之间的五种关系

> 讨论日期：2026-10-23。已实现三种（定位、关联、前置），派生待做（G4），**替代不做**（理由见 §5）。
> 关联：`design/graph重构与学科粒度.md` §9.2（派生）/ `references/recording.md` §6.6（关联）

---

## 判据：一条关系必须绑定一个行为变化

**加一种边之前，先能说出「它让系统的哪个行为变了」。** 说不出来就是装饰，
而且每多一种边，schema、报告、迁移、用户理解都要多一份成本。

| # | 关系 | 方向 | 改变的行为 | 状态 |
|---|---|---|---|---|
| 1 | **定位** | 门类 → 学科 → 课程 → 知识点 | 导航、聚合、报告折叠、盲区统计 | ✅ 3.8.0 |
| 2 | **关联** | 知识点 ↔ 知识点 | 回答时的联想与跨域迁移 | ✅ 3.5.0 |
| 3 | **派生** | 核心 → 派生 | **不记派生的条目也能估掌握程度** | ⬜ G4 |
| 4 | **前置** | A → B（学 B 前需会 A） | **讲解顺序 + 可疑标记** | ✅ 3.9.0 |
| 5 | **替代** | 新 → 旧（旧已作废） | 过期提示 | ❌ **不做** |

## 1. 定位（已实现）

**结构边，不是文件里的一条边。** 由目录与 frontmatter 承载：
`category` → `subject` → `course` → 知识点。

- 改变什么：报告按门类折叠、盲区按学科统计、「这个门类我有多广」
- 为什么不做成显式边：它是一棵树，用字段表达比用边表达省一个数量级
- 例外的门类：`生活常识` 的二级是**时代**（`跨时代` / `2020s`），不是学科

## 2. 关联（已实现）

**平的、无方向的、可以弱。** 由证据共现产生，三档：`auto` / `suggest` / `manual`。

- 改变什么：回答问题时「顺便提一句相关的」；跨域迁移的候选
- 存储三层：本体 `related:` / 展示正文 wikilink / 决策 `edges.md`
- 边界：**关联不蕴含任何逻辑**。「A 和 B 常一起出现」不等于「A 能推出 B」

## 3. 派生（G4 · 待做）

**逻辑蕴含：由 A 能推出 B。** 数学原理、物理公式、公理 → 大量具体结论。

- 改变什么：**估分**。用户掌握了核心 A，就能估出「大概率也会 B」，而不必逐条记录
- 与先验的区别：只抬高 `prior_exposure`（待验证清单），**不能直接给分**——
  否则就是「因为你懂微积分，所以你会解这道题」的假分
- 约束：只有 `importance: 1.0` 且**真的可推导**的条目才出边；一条派生最多 1–2 个来源
- 收益：这是「用最少最核心的内容塑造掌握情况」的机制。没有它，骨架只能枚举

## 4. 前置（已实现 3.9.0）

**学习顺序：不会 A 基本不可能真的会 B。** 无方向性蕴含，只讲先后。

- 存储：知识点 frontmatter `prerequisite: [名字]`；骨架里写 `- 条目 ⭐⭐ ← A、B`
- 建立：`link.py --user <id> --prereq "B" "A"`，**加边前查环，成环直接拒绝**
- 审计：`link.py --user <id> --prereq-audit` → 可疑 / 断链 / 成环
- 使用：`query.py` 输出「④ 前置」，`report.py` 第九节列可疑条目
- 首批预置 11 条（数学分析链 9 条 + 数据结构 2 条），其余靠 agent 建议 + 用户确认

| | 派生 | 前置 |
|---|---|---|
| 例子 | 极限 → 导数（既派生又前置） | 变量与作用域 → 闭包（前置，但不派生） |
| 语义 | A 在逻辑上蕴含 B | 学 B 之前得先会 A |
| 改变什么 | 估分 | **讲解顺序** + **可疑标记** |

- 用途 1：讲解时先补前置，而不是硬讲。「你想学闭包，先确认作用域」
- 用途 2：**一致性检查**。用户标了「懂 B」却「不懂 A」，那 B 需要复核——
  这是报告里「可疑条目」的来源，比单纯的待验证清单更有指向性

## 5. 替代（提案）

**A 取代了 B：B 曾经对，现在过时。** 时代真正需要的那条边。

- 改变什么：**过期提示**。讲 B 时说「这条已被 A 取代」，而不是让用户学到旧规则
- 为什么不能用衰减代替：民法典替代合同法不是遗忘，是作废。衰减只能让分数变低，
  说不出「去看哪一条」
- 与关联的区别：关联是「有关」，替代是「别用这个了」
- 与时代的关系：`subject: 2020s` 说「这条属于哪个时代」，
  `supersedes` 说「它被谁取代」。两者一起，才能算出「你现在还该懂什么」

## 不单列的三种

| 候选 | 为什么不做成独立边 |
|---|---|
| **同义／别名** | 不是边，是字段：`aliases`（骨架里写 `（又称 …）`） |
| **易混淆**（协程/线程） | 用 `related` + 标签 `contrast` 表达。单列会让边类型膨胀，而用途（出选择题）还很远 |
| **实例／例证** | 归入派生：抽象原理 → 具体案例，就是一次推演 |

---

## 边多了会怎样（要提前防的）

1. **互相矛盾**：A 派生 B，同时 B 又是 A 的前置——环。规则：派生与前置都必须是 DAG，
   写入前检查可达性，成环直接拒绝
2. **语义漂移**：用户把「感觉有关」记成派生。规则：派生边**必须能一句话说出推导过程**，
   说不出来就降级成关联
3. **维护成本**：每条边都是人工确认过的决策。所以默认只建议、不自动建，
   一次最多 3 对（与 `link.py` 的既有约束一致）
