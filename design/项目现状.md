## 1. 这是什么

把一个人的**知识 / 技能 / 经验 / 判断 / 行为**量化成可长期累积的能力档案。

三条硬约束决定了它的形状：

1. **纯文档**。每条记录是一个 `.md` 文件，Obsidian 打开就能看知识分布、能看图谱。
2. **可累积**。分数由证据推进，久了会衰减，不是一次性测评。
3. **不写假分**。没有证据就不给分——这条排第一，下面所有设计都为它让路。

## 5. 已经定死的决定（不要重新讨论）

1. **参照系只做标签，永不写分。** 否则等于把公共分类当成个人证据，违反不变量 I2。
   也因此换分类标准不触发档案迁移。
2. **跨领域知识不做成目录，做成图上的横向边。** 连边由 agent 建议 + 用户确认，建议必须带依据。
3. **三实体，两套分数，互不推导。** 知识分来自学习证据，技能分来自行为证据；
   一旦互相推导，`gap` 这个指标就不存在了。
4. **先验永不参与算分。** `prior_exposure` 只用于产出「待验证清单」，有实测证据后退为背景。
5. **学科骨架只装「能被某门课教的东西」。** 沟通话术、报税流程这类东西归技能或 Playbook。
6. **章节号 §0–§10 跟着内容搬家，不重编号。** 改标题时号本身也必须留着，否则锚点失效。
7. **知识点文件名 = 知识点名。** 撞名加「（学科）」后缀，但 `id` 始终取自 frontmatter。
8. **不把用户群收窄成「知识工作者」。** 这个项目是做给所有人用的。

## 6. 踩过的坑（别踩第二次）

| 症状 | 根因 | 现在的规矩 |
|---|---|---|
| 47 个文件全被加「（学科）」后缀 | `core.point_path` 把文件自己的路径当撞名 | 迁移里必须显式判断 `plain != path` 才 rename |
| 改完内容读到旧分数 | 索引缓存靠目录签名（mtime + 文件数）失效，改内容不改签名 | 写完必须调 `core.invalidate(udir)` |
| 录入通道静默断掉 | 改名后 `ingest.py` 仍拼 `points/<id>.md` | 一律走 `core.find_point`，支持 id / 名字 / 文件名 |
| 权重表两处不一致、手工口径系统性偏高 | 文档里抄了一份配置表，改 `_meta/` 时没校抄件 | 抄件必须写「以 `_meta/` 为准」；改主表顺手校 |
| `§0.8` 引用断掉 | 改标题时把章节号删了 | 只能改章节号**后面**那段描述 |
| 两条 50 分种子被算成 75 | 种子走了累加公式 | 种子直接赋值，仅在 `raw=0` 时生效，显式标 `role: seed` |
| 19 条有分没证据（违反 I2） | 冷启动直接写 `raw_score` | 一律写等值种子证据，分数回填 |
| 长命令被 SIGTERM、输出被吞 | Python 缓冲 + 默认 120s 超时 | 用 `-u`，写脚本文件跑，别用长 `-c` |
| 一次查询要 38 秒 | 本机每次 `open()` 固定开销约 23ms；查询逐条读 500 个文件，且 `apply_decay` 每条都重读一次配置 | 读全库一律走 `core.index_points`（落盘缓存）；配置读取带进程内缓存；**循环里不许调会 open 文件的函数** |
| 问「定积分」答成「不定积分」 | 匹配分 = 2-gram 重合 ÷ 名字长度，**长名字被单方面惩罚** | 按词块（与/和/、切开）+ 整块命中计分，只中一部分打折 |

## 8. 路线

**下一步：`graph/` 四层重构 + 按背景精度定铺设粒度。**
方案见 `design/graph重构与学科粒度.md`。**四个决策都已定**：
D1 用 11 个门类（10 个 ISCED-F 域 + 生活常识）／
D2 中间层可建文件但只装结构、**知识点集中在叶节点**并互相建链接／
D3 测试阶段不扩张（493）／ D4 三档粒度 + 强制确认环节。
分期：G1 结构迁移（37 学科，条目数不变）/ G2 按需建文件 + 扩到 800–1200 /
G3 联网补到 ~100 学科。

**「按需建文件」是 G2 的事，别提前做**：G1 条目数不变，先把结构搬对；
等条目真要增长时再启用，否则一次改两件事，出问题分不清是哪边。

之后：**S5 群体层**——候选簇匿名聚合。只有群体共识与维护者才能产「学科」，个人层只能产候选。
