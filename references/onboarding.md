# 启动协议：建档、采集背景、冷启动推断

> **管什么**：把新用户从「什么都没有」带到「档案可用」，且尽量少打扰他。
> **何时读**：`bootstrap.py --check` 返回 `new` / `partial`，或用户刚说出自己的背景。
> **读完回**：`SKILL.md` §1 场景路由表。

---

## 状态机

```
   没有档案                有档案但信息不全            档案可用
    new  ──采集三项背景──▶  partial  ──补齐缺项──▶    ready
     │                        ▲                        │
     └──用户说「先跳过」───────┘                        │
                              └──── 以后聊到背景再补 ────┘

   ready   稳态。到此后永不再问背景。
   partial 过渡态。只补缺的项，已有的绝不重复问。
```

最常见的错误是**在 `ready` 状态下又问一遍背景**——用户会觉得这系统没记住他。

---

## 0.1 检查

> 本文及后文所有命令，**工作目录是本 Skill 根目录**（`SKILL.md` 所在目录）。
> 目录不对先 `cd`；找不到根目录就按「无脚本」形态处理。

```bash
python3 scripts/bootstrap.py --check --user <user_id>
```

按它的输出执行。需要程序化判断加 `--json`，返回 `action: ask_background | proceed`。

| 状态 | 你的动作 |
|---|---|
| `new` | 用 §0.2 的话术**主动问背景** |
| `partial` | 只问缺的那几项，已有的不重复问 |
| `ready` | **直接办正事，不再提背景** |

## 0.2 采集话术

> 照用，语气可微调，**不要改成逐项追问**。

> 我想先把你的知识档案建起来，这样以后回答时能按你的实际水平来讲，
> 也能告诉你哪些知识正在生疏。需要三件事，一两句话说完就行：
>
> 1. **学历 / 专业**：比如 计算机本科、高中、机械硕士、自学
> 2. **职业 / 年限**：比如 前端工程师 5 年、教师、学生、自由职业
> 3. **生活 / 工作区域**：比如 杭州、北京、上海、海外
>
> （不想说也没关系，说一句「先跳过」，我按空白档案开始，后面聊到再补。）

**一次问清三项，不逐项追问。** 用户一句话带过（「计算机本科，在杭州做前端五年」）
就从中提取，**不要因为格式不规范要求重填**。

## 0.3 建档

```bash
python3 scripts/init_profile.py --user <user_id> \
    --edu "<学历>" --job "<职业>" --region "<区域>"
```

用户明确跳过：

```bash
python3 scripts/init_profile.py --user <user_id> --skip-onboarding
```

铺整套学科骨架、全部分数记 0，状态记 `partial`，以后聊到背景再补。

> 硬保证：补充模式**只给分数仍为 0 的知识点赋值**，不覆盖已积累的分。

**无脚本形态的建档**：按 `manual-mode.md` §0.8 手工建 `users/<id>/profile.md` 与空的六轨目录。

## 0.4 建完档必须做：一次性告知

> **「轻量」的标准（照此执行）**：一句话给总量 + 最多 6 个例子 + 一句请他来纠错，
> 总共不超过 3 行。目的是让他有机会说「这个标错了」，**不是让他逐条审阅**。

> 根据你「计算机本科 + 前端 5 年 + 杭州」，我初步标记了约 N 个知识点，
> 把握较高的有：事件循环、渲染管线、React 工程化、电商业务流程。
> 有标错的随时说，我会改。

**N 与例子必须取自脚本或查询的真实输出**，不得凭印象编。

## 0.5 不该问的情况

命中任一条就直接进正常流程：

- 状态已是 `ready`
- 用户明说「别问了 / 先跳过」→ 记 `partial`，不再追
- 只是随口问一句、明显无意建档 → 不勉强，但**仍可静默记录本次触及的知识点**
- 已问过一轮未获回应 → 按跳过处理，不追问

## 0.6 拿不准时主动问用户

> 本节是「问用户」，`expansion.md` 是「问网络」。顺序是先问用户，问不出再检索。

**触发条件**（满足任一）：背景模糊不完整（只说「学生」，没说方向）／推断出多种可能排不出优先级／
涉及跨学科，不确定他接触过没有。

| 补什么 | 问什么 | 示例 |
|---|---|---|
| 学过哪些科目 | 给清单让他勾，不要空手答 | 「你学过哪些课程？可多选：数据结构、操作系统、数据库、编译原理、计算机网络、离散数学…」 |
| 掌握到什么程度 | 给档位自评，不用开放式问法 | 「对这些概念，你大概是：完全陌生 / 听说过 / 能讲原理 / 能上手做 / 能教别人」 |
| 实际做过什么 | 项目、技术栈、代码量级 | 「你做过什么项目？用过哪些技术栈？代码量大概多少？」 |
| 现在想学什么 | 当前方向，用于调推断优先级 | 「你目前在学什么方向？AI、后端、前端还是其他？」 |

**话术模板**：

> 你提到是计算机方向的学生，但我想确认几个细节，这样推断会更准：
> 1. 你学过哪些专业课？（可多选：数据结构、操作系统、数据库、计算机网络、编译原理、离散数学…）
> 2. 你做过什么项目？用过哪些技术栈？
> 3. 你目前在学什么方向？

**四条原则**：

- 问题要**具体可回答**，不问「你还想知道什么」这类开放式的
- **给选项**而非空白填空（填空要他想、要打字，成本高得多）
- **一次问完**，最多 4 项，不连环追问
- 问完**立即写入档案**，问了不记等于白问

## 4. 冷启动：从背景推出他会什么

**策略：只记「现在还记得的」和「有据可查的」**，其余留空，用到再补。
几十年的知识不可能一次录完，这套系统是「用得越久越准」。

### 五条推断路径

| 从哪推 | 怎么推 | 例子 | 执行者 |
|---|---|---|---|
| 学历 | 专业与学位 → 必然修过的课 → 那门课的核心概念 | 计算机本科 → 数据结构、操作系统 | `inference/学历映射.md` |
| 职业 | 职业与年限 → 高频使用的技能 | 前端五年 → React 工程化、性能优化 | `inference/职业映射.md` |
| 区域 | 地域、语言环境、当地产业 | 杭州 → 电商与支付业务认知 | `inference/区域映射.md` |
| 联网检索 | 查该背景的培养方案、岗位要求、行业资料 | 计算机专硕 → 培养方案里的课程与能力项 | `expansion.md`（**兜底，也是主要扩展手段**） |
| 网络知识 | 他平时在搜什么、看什么 | 在学 AI → Transformer、RAG、强化学习 | `answering.md` §5.1 |

前三条由 `inference/*.md` 静态模板驱动。**关键词从用户原话里反着找**——
先看模板有哪些章节词，再看原话命中哪一段；不是截取输入前几个字
（用户填「2026 级燕山大学计算机技术专业研究生」时，截前三个字得到「202」，
所有章节都匹配不上，整条推断静默失效）。

**无脚本形态没有静态模板**：前三条无表可查，以第四条（联网检索）为主，
按背景逐面检索，自行归纳知识点归属。

### 推断之后怎么处理

```
采集背景 → 生成推断项（origin=inferred，权重 5）
        → 一次性批量告知，不逐条问
        → 用户确认 → 权重升到 12
        → 用户否认 → 标 rejected: true，不再参与计算
        → 背景不够 → 走 §0.6 问用户
```

**推断权重（5）刻意低于用户自评（8）**：人口统计学推断覆盖广但精度低，
擅长猜「大概接触过」，不擅长判断「到底会不会」。让它污染真实分数是系统烂掉的最快方式。

### 三条红线

- ❌ **不推断敏感属性**：健康、政治立场、宗教、性取向，一个都不碰
- ❌ **区域只推产业与语言环境**，不推个人特征（推「杭州电商产业发达」可以，推「杭州人偏好稳定」不行）
- ✅ **每条推断都要能说出依据**：「因为你说了 X，所以我推断 Y」。说不出依据的不许入库
- ⚠️ 背景不足时**主动问**（§0.6），不自行猜测

---

`ready` 之后回 `SKILL.md` §1 第 4 条，进入正常问答（细则在 `answering.md`）。
