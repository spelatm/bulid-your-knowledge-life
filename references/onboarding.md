# 启动协议 · 建档与冷启动推断

> **本文是 `SKILL.md` 的子文档**，装 §0.1–§0.6 与 §4 的完整规程。
> **何时读**：`bootstrap.py --check` 返回 `new` / `partial`，或用户刚说出自己的背景。
> **读完**：回到 `SKILL.md` §1 场景路由表继续，不要停在本文。

## 状态机总览（先看这张图，别搞错自己在哪）

```
   new ──采集三项背景──▶ partial ──补齐缺项──▶ ready
    │                      ▲                    │
    └──用户说"先跳过"───────┘                    │
                            └──── 后续聊到背景再补 ┘

   ready = 稳态。进入 ready 后：永不再问背景，直接进正常流程。
   partial = 过渡态。只补缺的项，已有的绝不重复问。
```

## 0.1 检查

> 本节及后文所有命令的**工作目录均为本 Skill 根目录**，即 `SKILL.md` 所在目录。
> 若当前目录不对，先 `cd` 过去；找不到根目录就自动降级到模式 B。

```bash
python3 scripts/bootstrap.py --check --user <user_id>
```

按输出的「下一步」执行。程序化判断加 `--json`，返回 `action: ask_background | proceed`。

| 状态 | 你的动作 |
|---|---|
| `new` | 用 §0.2 的话术**主动向用户采集背景** |
| `partial` | 只问缺的那几项，已有项不重复问 |
| `ready` | **直接进入正常流程，不要再问背景** |

## 0.2 采集话术（照抄，可微调语气，但不要改成逐项追问）

> 我想先把你的知识档案建起来，这样以后回答时能按你的实际水平来讲，
> 也能告诉你哪些知识正在生疏。需要三件事，一两句话说完就行：
>
> 1. **学历/专业**：比如：计算机本科、高中、机械硕士、自学
> 2. **职业/年限**：比如：前端工程师 5 年、教师、学生、自由职业
> 3. **生活/工作区域**：比如：杭州、北京、上海、海外
>
> （不想说也没关系，说一句「先跳过」，我按空白档案开始，后面聊到再补。）

**一次问清三项，不要逐项追问。** 用户可能一句话带过
（"计算机本科，在杭州做前端五年"），从中提取即可，不要因为格式不规范要求重填。

**补充模式只给 `raw=0` 的知识点赋分，不会覆盖已积累的分数**——这是硬保证。）

## 0.4 建档后必须做：批量轻量告知

> **「轻量」的定义（照此执行，不要超）**：
> **一句话总量 + 一组（≤6 个）例子 + 一句纠错邀请**，总共不超过 3 行。
> 目的是让用户能开口纠错，**不是**让他逐条审阅。

> 根据你「计算机本科 + 前端 5 年 + 杭州」，我初步标记了约 N 个知识点，
> 把握较高的有：事件循环、渲染管线、React 工程化、电商业务流程。
> 有标错的随时说，我会改。

其中 **N 与例子一律取自脚本/查询的真实输出**，不要凭印象写。
（模式 B 下按 `manual-mode.md` 自行统计后填。）

## 0.5 不该问的情况（命中任一就不问，直接进正常流程）

- 状态已是 `ready`
- 用户明说"别问了 / 先跳过" → 记 `partial`，不再追问
- 用户只是单次问答、明显无意建档 → 不强制，但**仍可静默记录本次提问触及的知识点**
- 已问过一轮未获回应 → 按跳过处理，不再追问

## 0.6 主动补充咨询（拿不准时）

> **定位：这一节是"问用户"，`expansion.md` 是"问网络"。先看能不能问用户，问不到再联网。**

**触发条件**（满足任一）：
- 背景模糊或不完整（如"学生"未说明专业方向）
- 推断结果存在多种可能，无法确定优先级
- 知识点涉及跨学科关联，需要用户确认是否接触过

| 补充项 | 你要问什么 | 示例 |
|---|---|---|
| **科目** | 给可选列表让用户勾选 | "你学过哪些课程？可多选：数据结构、操作系统、数据库、编译原理、计算机网络、离散数学…" |
| **掌握程度** | 让用户自评，给档位 | "对这些概念，你的掌握程度是：完全陌生 / 听说过 / 能讲原理 / 能上手做 / 能教别人" |
| **能力信息** | 项目、技术栈、代码量级 | "你做过什么项目？用过哪些技术栈？代码量大概多少？" |
| **学习目标** | 当前方向，用于调整推断优先级 | "你目前在学什么方向？AI、后端、前端还是其他？" |

**话术模板**：

> 你提到是计算机方向的学生，但我想确认几个细节，这样推断会更准：
> 1. 你学过哪些专业课？（可多选：数据结构、操作系统、数据库、计算机网络、编译原理、离散数学…）
> 2. 你做过什么项目？用过哪些技术栈？
> 3. 你目前在学什么方向？

**四条原则**：
- 问题要**具体可操作**，不问"你还想知道什么"这类开放式问题
- **给选项**而非空白填空，降低回答成本
- **一次问完**（≤4 项），不要连环追问
- 问完**立即写入档案**，不要问了不记（这是最容易犯的错）

## 4. 冷启动：背景推断

**策略：只录"现在还记得的"和"有据可查的"**，其余留空，随用随补。
几十年的知识不可能一次录完，这套系统是"用得越久越准"，不是一次建成。

### 五条推断路径

| 维度 | 依据 | 例子 | 谁来执行 |
|---|---|---|---|
| **学历层级** | 专业与学位 → 必然修过的课程 → 核心知识点 | 计算机本科 → 数据结构、操作系统 | `inference/学历映射.md` |
| **工作类型** | 职业与年限 → 高频使用的技能簇 | 前端五年 → React 工程化、性能优化 | `inference/职业映射.md` |
| **生活区域** | 地域/语言环境/行业生态 | 杭州 → 电商与支付业务认知 | `inference/区域映射.md` |
| **联网检索** | 检索该背景的培养方案/岗位要求/行业资料 | 计算机专硕 → 培养方案里的课程与能力项 | `expansion.md`（**兜底，也是主要扩展手段**） |
| **网络知识** | 用户浏览/搜索的主题、常访问领域 | 在学 AI → 关注 Transformer、RAG、强化学习 | `answering.md` §5.1 |

前三条由 `inference/*.md` 静态模板驱动——关键词**从用户原话反向提取**
（先读模板里有哪些章节词，再看用户哪段原话命中了它），
而不是截取用户输入的固定前几位，避免整句话背景导致零命中。

**模式 B 下没有静态模板**：前三条无表可查，直接以第四条（联网检索）为主，
按背景逐面检索后自行归纳知识点归属的学科与课程。

### 推断的处理

```
采集背景 → 生成推断项（origin=inferred, w=5）
        → 批量轻量告知（不逐条问）
        → 用户确认 → 权重升到 12
        → 用户否认 → rejected: true，不参与计算
        → 背景不足 → 主动补充咨询（见 §0.6）
```

**推断权重（5）刻意低于用户自评（8）**：人口统计学推断覆盖广但精度低，
不能让它污染真实分数。

### 推断红线

- ❌ 不得推断敏感属性（健康、政治立场、宗教、性取向）
- ❌ 区域维度只推产业与语言环境，不推个人特征
- ✅ 任何推断必须可追溯依据（"因为你说了 X，所以我推断 Y"）
- ⚠️ 背景不足时**主动咨询**，不自行猜测（见 §0.6）
