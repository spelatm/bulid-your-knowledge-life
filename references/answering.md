# 回答流程 · 报告 · 交互规范

> **管什么**：用户提问时怎么办、想看分布时怎么办、说话的分寸。
> **何时读**：用户提出讲解 / 教学 / 咨询 / 复盘 / 选型 / 学习计划类问题，或要看知识分布。
> **读完回**：`SKILL.md` §1 场景路由表。

## 5. 提问流程

先判断该不该走本流程（走错这一步后面全白搭）：

```
用户提问
   ├─ 纯事务请求（写邮件、翻译、算数、查天气、纯查资料）→ 直接办完结束，不查档案、不写日志
   └─ 讲解 / 教学 / 咨询 / 复盘 / 选型 / 学习计划类 → 往下走
```

> 排除纯事务的理由：一个人问「翻译这段话」与他的知识结构无关，
> 这时查档案只是让他多等几秒，还可能让回答变得莫名其妙地啰嗦。

### ① 档案存在吗

不存在 → 先正常回答这个问题，末尾顺带问一次背景（话术 `onboarding.md` §0.2）。
不要因为没档案就拒绝回答，也不要为建档打断他正在问的事。

### ② 查档案

```bash
python3 scripts/query.py --user <id> --q "<用户的问题>"
```

返回六段，**不要只读第一段**：

| 段 | 内容 | 怎么用 |
|---|---|---|
| ① 知识点状态 | 涉及哪些知识点，各自什么水平 | 决定讲多深（见 ③） |
| ② 经验 Playbook | 他在类似场景用过什么流程 | 按他那套走，并说明「这是你上次做 XX 时的做法」 |
| ③ 智慧原则 | 他自己总结过的判断原则 | 直接套用，不要另立一套 |
| ④ 横向关联 | 他在别处还用过这些概念 | 举例可顺着这条线，比通用例子有说服力 |
| ⑤ 相关技能 | 他手上会不会做 | 结合错位判断该补原理还是给练习 |
| ⑥ 画像特征 | 他偏好的表达方式 | 调整讲法：要例子？要结论先行？ |

### ③ 按查到的水平决定讲多深

同一个问题对不同人讲成不同样子，这是本系统最核心的一步。

| 档案状态 | 怎么讲 |
|---|---|
| 未触及 | 当全新知识讲，补前置背景，不假设他懂任何相关概念 |
| 听说过 | 先补一层背景再进主题，可用类比带过 |
| 理解原理 | 默认懂原理，重点讲**怎么用、有什么坑** |
| 能上手做 | 默认会做，直接进深水区与边界情况 |
| 精通 | 只讲增量与例外，不重复已知内容 |
| 生疏了 | 先一句唤醒（「这个你以前深入过，有段时间没碰了」），再展开 |

### ④–⑥ 用上经验、原则、表达偏好

- 有 Playbook → 按他那套流程处理，并说明来源（哪次项目）
- 有智慧原则 → 直接套用
- 有画像特征 → 调整表达方式

### ⑦ 回答完之后落一笔

- 写一条问题日志（E 轨）
- 本轮暴露遗忘 → 补一条负向证据

### 拿不准时

背景不足 / 推断有歧义 / 跨学科不确定 → 走 `onboarding.md` §0.6 问用户，不自行猜测。
问到的结果**写进档案**，并调整推断权重。

### 节流规则

- **同一次回答只查一次档案**，不要为每个子问题重复查
- **同一会话内同一知识点只记一条证据**，把 note 合并完整
- 查询或写入失败 → **不阻塞回答**，答完末尾说明一句
- 用户问的是全新领域 → 仍要查一次，用来判断「这是他的盲区」而非硬套深度

### 5.1 用户给了链接、论文或资料

六步：

1. **抓概念**：从网址、文献或他的描述里提炼核心知识点
2. **结合背景**：按已录入的学历、职业、区域过滤，调整置信度
3. **生成推断项**：标 `origin: inferred`、权重 5 起；确认后升为 `user_confirmed`
4. **写证据**：记下来源 URL 或文献，关联到知识点，更新分数
5. **背景不够**：走 `onboarding.md` §0.6 问，不猜
6. **量大的情况**：超过 10 条就走 `expansion.md` 的 `expand_profile.py`（无脚本则手工落盘）

> 与 `expansion.md` 的分界：这里是「一次对话里顺手抽几条」，那边是「按背景逐面检索、成批灌库」。
> 超过 10 条换那边，手工一条条抽容易漏也容易重复。

## 7. 生成报告

```bash
python3 scripts/report.py --user <id>                # 终端摘要（短）
python3 scripts/report.py --user <id> --save         # 完整报告，存 users/<id>/reports/
python3 scripts/report.py --user <id> --subject 数学   # 单学科
```

完整报告八节：总体概览 / 域分布（广度 × 深度）/ 掌握度分层 / 正在生疏 /
盲区提示 / 待验证与待确认 / 近期动态 / **技能与错位**。
**终端摘要只含前几节，完整八节需 `--save`。**

### 八节的设计约束（回答用户时也要守住）

- **全库均值与已触及均值并列**：全库均值把未触及项计入分母，会低得吓人；
  只给一个数，用户会误读为「我很差」，其实只是「还没学」
- **盲区按「已有积累的学科」优先排**：数学没学对前端不是缺口，计算机科学里的才是
- **未触及的域折叠成一行**：骨架全铺保证「位置一直在」，但展示不折叠会被一排 0% 淹没
- **猜测与实测视觉分离**：`prior_exposure` 推出的「待验证清单」必须标为**猜测**，
  绝不与 `raw_score` 混在一张表里
- **无行为证据的技能折叠到簇里**：23 个技能全列是一面 0 分的墙，但删掉也不对；
  折成「人际沟通 8 个」比两种极端都好
- **错位只说方向，不评价人**：说「这个技能你手熟但原理淡了」，不说「你的理解很浅」

## 9. 交互规范

### 9.1 必须确认的时机

- 推断出一批知识点 → **批量**轻量告知，不逐条问
- 一个问题命中多条相似知识点 → 确认是哪一条
- 要记负向证据 → 用中性表述，避免「扣分」感
- 要归档或删除 → 二次确认
- **要改系统** → 走 `improving.md` §8 完整流程

### 9.2 输出模板

| 场景 | 这么说 |
|---|---|
| 刚建完档 | 铺了多少条 → 哪几块把握较高 → 怎么改 → 以后怎么补 |
| 用户要看分布 | 域 × 广度/深度 → 强项 → 盲区 → 待验证清单 → 正在生疏前几名 |
| 问到「生疏了」的知识 | 一句唤醒 → 「你当时是在 XX 场景下掌握的」→ 再展开 |
| 遇到同类事件 | 调出 Playbook → 说明来源（哪次项目）→ 按流程推进 |

### 9.3 语气红线

- **不做评判**：不说「你这方面很弱」，说「这块的证据还比较少」
- **遗忘中性化**：不说「你忘了」，说「这个有一段时间没碰了」
- **推断透明**：任何推断都要能说出依据，说不出依据就是编造
- **不夸大**：库里没有就说没有，不编未命中的内容凑完整答案
