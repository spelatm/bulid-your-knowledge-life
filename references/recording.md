# 录入：证据、四类记录、横向边、技能

> **管什么**：用户说了一件值得记的事，把它变成档案里的记录。
> **何时读**：用户说「我做过」「我会」「我一般是」「这条不对」「这两条有关系」，或一次回答结束要落盘。
> **相关**：算分公式在 `model.md` §3；无脚本做法在 `manual-mode.md` §0.8。
> **读完回**：`SKILL.md` §1 场景路由表。

---

## 6.1 录入证据

```bash
python3 scripts/ingest.py --user <id> --target <知识点> \
    --type project_lead --note "主导支付重构"
```

`--type` 决定权重与置信度（对照 `model.md` §3.1）。`--note` 写清**当时到底发生了什么**——
半年后回看，这行字是唯一线索。

忘了知识点叫什么：

```bash
grep -rl "name: 性能优化" users/<id>/points/
```

### 一条证据同时点几个知识点

```bash
python3 scripts/ingest.py --user <id> \
    --target "消息传递机制" --target "谱图理论" \
    --type artifact --note "复现 GNN 过度平滑时，这两个概念同时用到"
```

这是系统最重要的命令。一条证据同时点到 A 和 B 即一次**共现**；
共现攒够了，系统才敢提议「这两条该不该连」。只用单目标，档案永远是一张平铺清单，长不出结构。

### 其它三种用法

```bash
# 记技能：分数进 level，不进 raw_score
python3 scripts/ingest.py --user <id> --skill --target "信息检索" --type project_lead

# 记遗忘：走乘系数，不是加权重
python3 scripts/ingest.py --user <id> --target "傅里叶变换" --type forgot

# 只刷新时间（让 current 回到 raw），不加新证据
python3 scripts/ingest.py --user <id> --target "消息传递机制" --verify
```

### 三个操作细节

- `--target` 接受 **id / 知识点名 / 文件名主干** 三者之一
- **查不到名字时不要猜 id**，先用 `query.py` 或 `grep` 确认
- 提示「未找到知识点」通常是名字不一致（错别字、简称、空格）；按别名对齐，
  **不要顺手新建重复条目**——重复比缺失更难收拾

## 6.2 B 轨：把做过的事记成经验

```
项目       目标、角色、起止、用到哪些能力        ← 必录
  └ 行动   流程、卡点、怎么解的                 ← 有时间就记
      └ 产物  文档 / 代码 / 设计稿 / 报告 / 链接  ← 有就记
```

**只有项目层必填**——要求全填的表最后一定变成空表。

### 记完项目要反过来点亮知识点

叫「反哺」：想清这个项目用到或印证了哪些知识点，生成证据点亮它们。

```bash
python3 scripts/ingest.py --user <id> --type project_lead \
    --target "知识点一" --target "知识点二" --target "知识点三" \
    --note "在 XX 项目里同时用到"
```

项目的 `touched_points` 有几个就 `--target` 几次。做完这一步，经验才真正连到知识上，
否则它只是孤零零一段回忆。

### 攒够两次以上，提炼成 Playbook

同类项目做过 **2 次以上**，可提炼一套 Playbook：适用场景 / 标准流程 / 已知坑位 / 关联知识点。
价值在于下次遇到同类事件直接调流程，不从零推演。

预置 7 个流程模板在 `templates/playbooks.md`（任务拆解与排期 / 优先级判断 / 会议组织 /
文档沉淀 / 复盘方法 / 风险管理 / 求职准备）。

> **模板不是用户的经验**：只有他的项目真跑通了才 `verified_count += 1`，没跑过标已验证等于替他吹牛。

## 6.3 C 轨：他怎么判断事情

两种时机：从多条经验里归纳出共性时；他说出「我一般是…」这类原则性表述时。

| 字段 | 填什么 |
|---|---|
| `statement` | 一句话，要能迁移到别的场景 |
| `domain` | 适用领域，`*` 表示通用 |
| `confidence` | 你有多确信这是他的稳定原则 |
| `source` | `derived`（你归纳的）/ `declared`（他说的） |
| `counter` | **反例或适用边界，必填** |

`counter` 必填的理由：没有边界的原则会变成教条，下次遇到不适用的场景还硬套会出事。
写不出边界说明还没到能提炼的时候，先别记。

## 6.4 D 轨：他是什么样的人

轻量特征卡，**一条只记一个特征，不写人物传记**。

必须区分来源（可信度不同）：`observed` 你观察到的 / `declared` 他明说的。

`observed` 记之前必须问一句：

> 我注意到你更习惯先看例子再看定义，要记下来吗？

他可否认或修正。**连续观察到 3 次以上**才建议记录——一次是偶然，三次才是习惯。

## 6.5 他说「这条不对」

标 `rejected: true`，此后不参与计算、不出现在报告里。**不要删文件**，
保留记录才能回答「当初为什么把这条排除了」。

> **与「改系统」分界**：他说「这条标错了」＝改一条数据，直接改（本节）；
> 他说「凭什么半衰期 90 天」＝质疑规则本身，走 `improving.md` §8。
> 判断标准：改的是一条数据，还是规则。

## 6.6 横向边：两条知识之间的关系

- **纵向边**：域 → 学科 → 课程 → 知识点。由 `graph/` 给出，公共的，所有人一样
- **横向边**：知识点 ↔ 知识点。**个人的**，只能长在档案里

横向边记的只有一件事：**「这两样东西他在同一个场景里一起用过」**。

```bash
python3 scripts/link.py --user <id> --suggest          # 找候选（够格的自动建）
python3 scripts/link.py --user <id> --accept "A" "B"   # 同意建议
python3 scripts/link.py --user <id> --reject "A" "B"   # 拒绝，此后不再问这一对
python3 scripts/link.py --user <id> --add "A" "B"      # 用户自己说这两条有关
python3 scripts/link.py --user <id> --list             # 现有全部边
```

三档，**不要越档**：

| 档 | 条件 | 动作 |
|---|---|---|
| `auto` 自动 | 同属一个域，**并且**共现 ≥3 次 | 直接建。建错可撤销，代价低 |
| `suggest` 建议 | 跨域，或共现 1–2 次 | **先问用户**，同意才建 |
| `manual` 手动 | 用户自己说这两条有关系 | 直接建 |

### 建议必须带依据

> 你在「复现 GNN 过度平滑」那次同时用到了『消息传递机制』和『谱图理论』，
> 这条线要连上吗？（依据：共现 3 次，证据 ev_a1、ev_b2）

- 一次最多 3 对（多了他记不住也答不完）
- 拒绝过的同一对**永不再问**（记录写进 `edges.md`）
- **没有依据不许提**——否则会开始随机连边，随机连出来的图比没有图更糟

### 一条边落在三处，各有各的用处

| 落在哪 | 长什么样 | 谁在用 |
|---|---|---|
| 两端 frontmatter | `related: [对方名字]` | 机器读，这是本体 |
| 两端正文 | `## 关联` 下的 `[[对方名字]]` | Obsidian 靠它画图 |
| `edges.md` | 谁、何时、凭什么连的 / 拒过哪对 | 人查账 |

建边同时写一条 `edge_confirm` 证据，**权重 0**——
「确认相关」推不出「你更懂了」，给它加分是逻辑错误。

> 正文 `## 关联` 由 `related` 生成，包在 `<!-- related:start -->` 与 `<!-- related:end -->` 之间，
> **不要手改**，下次同步会覆盖。

## 6.7 技能：他会不会做

```bash
python3 scripts/skill.py --user <id> --seed        # 铺预置技能簇，熟练度全 0
python3 scripts/skill.py --user <id> --requires "信息检索" --points "信息检索,资料筛选与判别"
python3 scripts/skill.py --user <id> --add "论文复现" --cluster 学术研究 --kind composite
python3 scripts/skill.py --user <id> --list        # 列表，含错位值
python3 scripts/ingest.py --user <id> --skill --target "信息检索" --type project_lead
```

### 两套分数，永不互相推导

| | 靠什么涨 | 存在哪 | 答什么 |
|---|---|---|---|
| 知识点 | `study` / `teaching` / `artifact` | `raw_score` | 他懂不懂 |
| 技能 | `project_lead` / `artifact` / `selftest_pass` | `level` | 他会不会 |

理由：一个人可能「会做但不懂原理」（老师傅），也可能「懂原理但没动过手」（刚读完书的学生）。
这两种人需要的帮助完全相反；若让技能分从知识点分推导，区别就消失了。

### 错位：简历答不出来的指标

```
错位 = 技能熟练度 − 这个技能要求的那些知识点的当前分均值
```

| 错位值 | 说明 | 怎么办 |
|---|---|---|
| **大于 +20** | 手熟但原理淡了，靠手感 | 补原理，多给推导 |
| **−20 到 +20** | 知行相当 | 正常讲 |
| **小于 −20** | 学过没实践，纸上谈兵 | 多给练习，少讲理论 |

简历只能答「你做过什么」，答不了「你手上会的和脑子里懂的是否一致」，
而这个错位恰好决定该补课还是该练手。

`requires` 为空的 `tacit` 技能（说不清依赖什么的手感）算不出错位，
**这是正常状态，不是数据缺失**，不要为凑数硬填。

### 什么情况下才建技能

三条都满足，缺一条就只记经验不建技能：

1. 他**做**过，不只是**学**过（技能分只认行为证据）
2. 有个名字能代表这个能力：要「信息检索」，不要「用 Google 很溜」（后者没法检索也没法对比）
3. 能说清它**依赖哪些知识点**（`tacit` 类除外）
