## 3. 量化模型

> 本节表格即配置本身。**与 `_meta/*.md` 冲突时以 `_meta/` 为准。**

模型只有三句话：**一次好证据往 100 分推一把，越接近 100 推得越慢；
一次忘掉的证据把分数打个折；时间过去，分数自动打折，不同内容打得快慢不同。**

### 3.1 正向证据累积

```
累计分 += (100 − 累计分) × (权重 / 100) × 置信度
```

**边际递减**：0→50 容易，80→95 极难。与真实学习体验一致，且天然带 100 分上限
（线性加分会让做了很多项目的人爆表，多出的部分毫无意义）。

| 证据类型 | 权重（推多少分） | 置信度（多可信） | 什么算这类 |
|---|---:|---:|---|
| `project_lead` | 35 | 0.9 | 主导完成了一个项目。最强证据，真用过 |
| `teaching` | 30 | 0.85 | 教过别人或写过讲解文章（费曼效应） |
| `artifact` | 25 | 0.85 | 有能拿出来看的东西：文档、代码、作品 |
| `selftest_pass` | 20 | 0.8 | 自测或复述通过 |
| `user_confirmed` | 12 | 0.7 | 他确认了我们的推断，推断升级为事实 |
| `study` | 12 | 0.6 | 系统学过：读完一本书、上完一门课 |
| `self_report` | 8 | 0.5 | 他自己说「这个我会」。最弱，只作冷启动铺底 |
| `inferred` | 5 | 0.4 | 从背景推出，他没确认过 |
| `web_inferred` | 5 | 0.4 | 从网上查来，他没确认过，须附来源 URL |
| `edge_confirm` | **0** | 1.0 | 确认两个知识点相关。**故意不给分** |

> 本表是 `_meta/weights.md` 的抄件，**以那个文件为准**——`ingest.py` 读的是它，
> 两边不一致时错的是本表。2026-10-18 抓到过一次：本表 5 行与 `_meta/` 不符，
> 导致完整仓库算得对、手工口径系统性偏高。改主表时顺手校本表。

`edge_confirm` 权重为 0 的理由：确认两条知识相关推不出「你更懂了」。
它只记录「谁、何时、凭什么连的」，可追溯但不进分。

#### 种子分（另一条路）

`role: seed`，冷启动与联网扩展用：**`累计分 = 权重`、只在累计分为 0 时生效、置信度固定 1.0**。
分档：`strong` 50 / `likely` 30 / `possible` 20。

必须与累加证据分开：走累加的话，两条 50 分种子会被算成 `50 + (100−50)×0.5 = 75`，
凭空多 25 分而中间什么都没发生。

#### 防刷分

**同一知识点证据超过 5 条后，新增证据权重按 `1/n` 递减。**

### 3.2 负向证据（遗忘）

| 事件 | 系数 | 什么情况 |
|---|---:|---|
| `forgot` | ×0.85 | 本该会却没想起来，或明说忘了 |
| `selftest_fail` | ×0.92 | 自测或复述失败 |
| `rusty_asked` | ×0.90 | 被标为生疏，且要求从头讲 |

**这是乘不是减**：分数越高扣得越多，分数低时几乎不痛不痒——
一门很熟的东西忘一点，损失比刚入门时忘一点大得多。

于是 `raw_score` 成为**证据净值**，可升可降。若只会涨不会跌，档案就成了自夸清单而非镜子。

### 3.3 时间衰减

```
当前分 = 累计分 × 0.5^(距上次验证天数 / 半衰期)
```

每过一个半衰期，剩余鲜活度减半。

| 档位 | 半衰期 | 适合什么 |
|---|---:|---|
| `volatile` | 45 天 | 词汇、外语、API 细节、版本号 |
| `tooling` | 90 天 | 工具、框架、软件操作、命令行 |
| `foundation` | 180 天 | 数理基础、核心概念、专业基本功 |
| `methodology` | 365 天 | 方法论、思维方式、设计原则 |
| `durable` | 730 天 | **技能**（会生疏，不会忘掉「会」） |
| `permanent` | 永不过期 | 母语、常识、基本生活技能 |

每日执行：`python3 scripts/decay.py --user <id> --apply`

### 3.4 状态判定

```
累计分 0                          → untouched   未触及
当前分 1–25                       → aware       听说过
当前分 26–50                      → understood  理解原理
当前分 51–75                      → applicable  能上手做
当前分 76–100                     → proficient  精通
当前分 ≤ 历史最高×0.6，且最高 ≥ 40 → rusty       生疏了
```

**`rusty` 是系统最有价值的状态**：标记的不是「不会」，而是**「曾经会、现在可能废了」**。
用户卡住时最难受的往往不是不会（不会就学，很简单），而是「我明明学过怎么想不起来」。
这时一句「这个你以前深入过，只是有段时间没碰了」比任何讲解都管用。

### 3.5 分层暴露

| 层 | 给谁 | 里面是什么 |
|---|---|---|
| L0 概览 | 用户 | 一句话或一张图 |
| L1 档案 | 用户 | 卡片级：等级、上次接触时间、证据摘要 |
| L2 证据流 | 机器 | 每条证据的类型、权重、时间、置信度 |
| L3 关系网 | 机器 | 知识点依赖、经验→知识点映射、原则溯源 |

**底层存连续分，展示时才折算等级**：用户不需要看到「63.4」，只需知道「能上手做」。

## 10.2 知识点字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` / `name` / `subject` / `course` | ✅ | 标识与归属：哪个知识点、什么学科、哪门课 |
| `raw_score` | ✅ | 累计分。证据净值，可升可降 |
| `current_score` | ✅ | 当前分 = 累计分打过折 |
| `peak_score` | ✅ | 历史最高，用于判断「生疏了」 |
| `last_verified_at` | ✅ | 最后一次验证的日期 |
| `profile` | ✅ | 衰减档位（45 / 90 / 180 / 365 / 730 天） |
| `importance` | ✅ | 1.0 核心 / 0.6 一般 / 0.3 边缘。聚合时按它加权 |
| `origin` | ✅ | 来源：`preset` 预置 / `inferred` 推断 / `user` 用户说的 |
| `evidence_ids` | ✅ | 支撑这个分数的证据 |
| `rejected` | ⬜ | 用户否认过的推断项 |
| `status` | ✅ | 状态名：未触及 / 听说过 / 理解原理 / 能上手做 / 精通 |
| `domain` | ⬜ | 域（10 选 1，只作索引；空 = 未归类）。**不参与算分** |
| `transferable` | ⬜ | 可迁移性 0–1。`≥0.7` 归入「通用与跨域方法」视图 |
| `context` | ⬜ | 适用语境（专业 / 生活） |
| `prior_exposure` | ⬜ | 先验接触概率 high/medium/low/minimal。**永不参与算分** |
| `related` | ⬜ | 横向边：相关知识点**名字**。正文「## 关联」由它生成 |

> 末四行加 `related` 都是**启发值或关系**：决定怎么展示、先问什么、连到哪儿，
> 不决定「你有多强」。取值规则全在 `_meta/domains.md`，改数值不用改代码。

完整字段定义见 `_meta/schema.md`，录入模板见 `templates/README.md`。

## 10.2b 技能实体字段（`experience/skills/`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` / `name` | ✅ | 标识 |
| `cluster` | ✅ | 能力簇：人际沟通 / 信息处理 / 工具与平台 / 职业素养 / 自建 |
| `kind` | ✅ | `composite` 可分解 / `tacit` 说不清依赖的手感（`tacit` 的 `requires` 可空） |
| `requires` | ⬜ | 依赖哪些知识点**名字**。技能通向知识的边 |
| `experience` | ⬜ | 在哪次项目里用过。技能通向经验的边 |
| `level` | ✅ | 熟练度 0–100。**只由行为证据推进**，不由知识点分推导 |
| `last_used_at` | ⬜ | 最后使用时间。`durable` 档从这天起算衰减 |
| `profile` | ✅ | 固定 `durable`（730 天） |
| `evidence_ids` | ✅ | 支撑熟练度的证据 |
