# references/ · 七份子文档

`SKILL.md` 是主文档，只装**角色、不变量、环境探测、场景路由表**。
每个具体动作的完整做法放在这里，**做完哪件事就只看那一份**，不要全读。

| 文件 | 管什么 | 什么时候读 |
|---|---|---|
| `onboarding.md` | 建档、采集背景的话术、冷启动推断 | 档案是 `new` / `partial`，或用户刚说出自己的背景 |
| `answering.md` | 回答一个问题的七步流程、报告八节、说话的分寸 | 用户提问、想看自己的知识分布 |
| `recording.md` | 证据怎么录、经验 / 原则 / 特征怎么记、横向边、技能 | 该往档案里写东西了 |
| `expansion.md` | 静态模板覆盖不了，去网上查了补进档案 | 建档时零命中，或用户递来网址文献 |
| `manual-mode.md` | 没有脚本时的全套手工做法 + 完整仓库地图 | 没有 `scripts/`，或脚本挂了要降级 |
| `model.md` | 分数怎么算、字段填什么、想调参数改哪 | 算分、判状态、改权重、查字段名 |
| `improving.md` | 改系统的五步流程、脚本清单、自检清单、禁区 | 用户想改系统本身，或会话收尾自查 |

**章节号 §0–§10 是跟着内容搬过来的，没有重新编号。**
所以 `scripts/` 里那句「见 §0.7」仍然指得准，只是那条规矩现在住在 `expansion.md` 里。
重编号的代价是：所有历史 CHANGELOG、设计文档、代码注释里的引用同时失效。

## 维护这份文档集的三条规矩

1. **一条规矩只写在一处。**
   如果发现同一句话在两份文档里都有，删掉一份，留一个指针。
   两份各写一遍的结局，一定是只改了一份。

2. **唯一允许的重复是 `SKILL.md` 的「最小闭环」。**
   那是给「只有一个文件」的人准备的兜底，故意重复了公式、权重表、衰减档位和字段模板。
   代价是：**改公式或档位时两处必须同时改**，而且最终以 `_meta/*.md` 为准。

3. **新增或删除子文档时，改三个地方**：
   `SKILL.md` 顶部的索引表、`SKILL.md` §1 路由表的「细节在哪」列、以及这里的表。
   漏掉任何一处，下一个人就会读错文档。
