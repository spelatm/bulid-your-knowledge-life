## 0.7 联网扩展档案（背景超出静态模板时）

> `onboarding.md` §0.6 是"问用户"，本节是"问网络"。静态映射表覆盖不到用户背景时，
> **不要就这么把档案交出去**——去检索，把它补上。

**触发条件**（满足任一即执行）：

- `init_profile.py` 输出「⚠️ 静态映射表零命中」
- 用户的专业 / 职业 / 地域在 `inference/*.md` 里找不到对应章节（新兴行业、交叉学科、海外背景、小众职业）
- 用户主动说「这个方向该会的都帮我补上」/「看看我这行还需要什么」
- 用户提供了网址、文献、培养方案等外部材料（与 `answering.md` §5.1 联动）

**执行流程**

**① 检索**（用联网工具，覆盖背景涉及的每一面）

| 背景面 | 检索什么 | 检索词构造 |
|---|---|---|
| 学历 | 专业培养方案、核心课程大纲、教材目录、学位要求 | 学校 + 专业 + 学位（如「计算机技术 专业硕士 培养方案 课程」） |
| 职业 | 岗位职责、能力模型、行业技能清单、常用工具链 | 岗位 + 年限 + 「能力模型 / 技能要求」 |
| 区域 | 区域产业与生态（**只推产业环境，不推个人特征**） | 城市 + 主导产业 |

**② 抽取知识点**：每条 = 名称 + 强度 + 依据 + **来源 URL**。
强度沿用 `inference/README.md` 口径：`strong` 几乎必然掌握 / `likely` 大概率接触 / `possible` 可能接触。

**③ 与骨架对齐**：优先复用 `graph/` 既有命名；命名不同先看别名（`（又称 …）`），
能对齐就不要另起一条。真的没有的才新建，按 `subject` / `course` 归位（缺省归「其他」）。
（模式 B 没有骨架 → 全部新建，`subject` / `course` 由你归纳，粒度保持稳定：一个方向一个学科。）

> 对齐前先想一件事：**这条东西能被某门课教吗？**
> 教不出来的（沟通话术、时间管理、报税流程）不是知识点，是技能或 Playbook——
> 塞进学科树会把「学科」稀释成「话题清单」（3.5.0 的教训）。

**④ 落盘（先试运行，再正式写入）**

```bash
python3 scripts/expand_profile.py --user <id> --input inferences.json --dry-run
python3 scripts/expand_profile.py --user <id> --input inferences.json
```

JSON 格式 `{background, sources[], points[]}`，`points[].source` **必填**。
命中骨架的给 0 分知识点赋种子分，未命中的建新条；
**每条都会写一条 append-only 证据**（含来源 URL），可审计。

**⑤ 批量轻量告知并请确认**：脚本末段会直接给出话术，照它执行。
用户否认 → 标 `rejected: true`，**不删文件**、不参与计算。

**红线**

- ❌ **没有来源的不许入库**。不可追溯的推断等于编造，宁可不推。
- ❌ 不把检索到的资料原文抄进档案。只存知识点名与依据摘要，原文留在来源链接里。
- ❌ 不推敏感属性（健康、政治立场、宗教、性取向等）；区域只推产业与语言环境。
- ⚠️ 联网结果一律 `origin: inferred` + 冷启动种子分（strong 50 / likely 30 / possible 20），
  **未经用户确认前不得当作"已掌握"来讲**；回答时应比静态推断再保守一档。
- ⚠️ 单次入库 ≤ 80 条。超过就分批，让用户逐批确认——
  档案一次灌太多会瞬间失真，而用户察觉不到。
