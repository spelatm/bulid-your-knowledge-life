## 0.7 联网扩展档案

> `onboarding.md` §0.6 是「问用户」，本节是「问网络」。先问用户，问不出再检索。
> 反过来：静态模板查不到时**不要就这么交出一份空档案**——去查，把它补上。

**触发条件**（满足任一）：

- `init_profile.py` 输出「⚠️ 静态映射表零命中」
- 用户的专业 / 职业 / 地域在 `inference/*.md` 里找不到对应章节
  （新兴行业、交叉学科、海外背景、小众职业都属此类）
- 用户主动说「这个方向该会的都帮我补上」「看看我这行还需要什么」
- 用户提供了网址、文献、培养方案等外部材料（与 `answering.md` §5.1 联动）

### ① 检索：背景每一面都要覆盖

| 查哪面 | 查什么 | 搜索词怎么构造 |
|---|---|---|
| 学历 | 专业培养方案、核心课程大纲、教材目录、学位要求 | 学校 + 专业 + 学位，如「计算机技术 专业硕士 培养方案 课程」 |
| 职业 | 岗位职责、能力模型、行业技能清单、常用工具链 | 岗位 + 年限 + 「能力模型 / 技能要求」 |
| 区域 | 当地产业与生态 | 城市 + 主导产业 |

> 区域只推产业环境，不推个人特征：推「杭州电商产业发达」可以，推「杭州人偏好稳定工作」不行。

### ② 抽取知识点

每条四样：**名称 + 强度 + 依据 + 来源 URL**。强度沿用 `inference/README.md` 口径：

| 强度 | 含义 |
|---|---|
| `strong` | 该背景下几乎必然掌握 |
| `likely` | 大概率接触过 |
| `possible` | 可能接触 |

### ③ 与骨架对齐

优先复用 `graph/` 既有命名；命名不同先看别名（`（又称 …）`）；能对齐就不要另起一条。
确实没有的才新建，按 `subject` / `course` 归位，归不了放「其他」。

（无骨架形态全部新建，`subject` / `course` 由你归纳，但**粒度保持稳定**：
一个方向一个学科，不要这次把「机器学习」当学科、下次当课程。）

> 对齐前先问一句：**这条东西能被某门课教吗？**
> 教不出来的（沟通话术、时间管理、报税流程）不是知识点，是技能或 Playbook。
> 塞进学科树会让整个骨架失去可比性（3.5.0 的教训）。

### ④ 落盘：先试运行再正式写

```bash
python3 scripts/expand_profile.py --user <id> --input inferences.json --dry-run
python3 scripts/expand_profile.py --user <id> --input inferences.json
```

输入 JSON 结构 `{background, sources[], points[]}`，**`points[].source` 必填**。

脚本做三件事：命中骨架的给原本 0 分的知识点赋种子分；没命中的建新条目；
**每条都写一条只增不改的证据**（含来源 URL），以后可倒查分数来历。

### ⑤ 告知并请确认

脚本末段会直接给出话术，照它说。用户否认的标 `rejected: true`，**不删文件**、不参与计算。

### 五条红线

- ❌ **没有来源的不许入库**——追溯不了的推断等于编造，宁可不推
- ❌ **不把检索原文抄进档案**——只存知识点名与依据摘要，原文留在来源链接
- ❌ **不推敏感属性**：健康、政治立场、宗教、性取向；区域只推产业与语言环境
- ⚠️ 联网结果一律 `origin: inferred` + 冷启动种子分（strong 50 / likely 30 / possible 20）。
  **未经确认不得当作「已掌握」来讲**，回答时比静态推断再保守一档
- ⚠️ **单次入库 ≤ 80 条**。超了分批确认——一次灌太多档案会瞬间失真，而**用户察觉不到**
