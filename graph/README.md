# 预置知识骨架

> 冷启动时铺给用户的知识树起点。**三层结构：门类 / 学科 / 课程。**
> 只有到「课程」才有文件；知识点是课程文件里的一行，落进用户档案时才成为独立文件。

## 布局

```
graph/
  信息与计算技术/                    门类（= 域，见 _meta/domains.md §1）
    计算机科学与技术/                学科
      数据结构与算法.md              课程索引
    软件工程/
      前端.md
  自然科学与数学/
    数学/
      代数.md
```

一个课程索引长这样：

```markdown
---
category: 信息与计算技术
subject: 计算机科学与技术
course: 数据结构与算法
profile: foundation
---

# 数据结构与算法

> 信息与计算技术 › 计算机科学与技术

- 时间复杂度分析 ⭐⭐
- 数组与链表 ⭐⭐
- 红黑树 ⭐〔tooling〕
```

**门类/学科/课程写在 frontmatter 里，路径只负责阅读。** 所以目录可以重组，
身份不变——这是「结构稳定」的落点，也是 `core.parse_graph` 优先读 frontmatter 的原因。

## 生活常识：二级是时代，不是学科

这一个门类的二级轴和别的门类不同——它讲的是「**此刻的人怎么过日子**」，
而价值认同与生活工具本身就带年代。

```
graph/生活常识/
  跨时代/          健康.md  急救.md  生活维修.md      ← 不随年代变
  2020s/           理财.md  法律.md  饮食.md  出行.md  ← 带年代
```

- 跨时代的放 `跨时代`，不跟着每个年代重写
- 带年代的放 `<年代>`；下个时代**新增**一个目录，旧的原样留着——
  `2020s/法律.md` 与 `2030s/法律.md` 并存，差异本身就是知识
- 所以这些条目的 `subject` 字段装的是**年代**，不是学科名

> 时代 ≠ 衰减。衰减回答「忘得多快」，时代回答「属于哪批人的共识」，
> 而「被取代」是另一条边（`supersedes`，见 `design/知识点关系类型.md`）。

## 三层各是什么

| 层 | 是不是实体 | 装什么 |
|---|---|---|
| 门类 | 否 | 无文件，只是一个目录（= `_meta/domains.md` 的 10 个域 + `生活常识`） |
| 学科 | 否 | 无文件（可选放 `README.md` 说明边界），不在任何统计里出现 |
| 课程 | **结构文件** | 条目清单 + `profile` 档位；不带 `id`、不带分数、不进 `points/`、不参与算分 |
| 知识点 | **实体** | 只有它会在用户档案里变成 `points/<名字>.md`，带分数与证据 |

## 书写格式

```markdown
- 知识点名 ⭐⭐
- 知识点名 ⭐〔tooling〕
- 知识点名（又称 别名一、别名二） ⭐⭐
- 知识点名 ⭐⭐ → 见 另一门课程        # 跨课程的引用标记，不复制条目
- 知识点名 ⭐⭐ ← 前置一、前置二       # 前置：不先会这些就讲不动这一条
```

| 标记 | 含义 |
|---|---|
| `⭐⭐` | 重要度 1.0（核心），`importance: 1.0` |
| `⭐` | 重要度 0.6，`importance: 0.6` |
| 不标 | 重要度 0.3，`importance: 0.3` |
| `〔tooling〕` | 这一条单独用某档衰减，覆盖课程默认 |
| `（又称 …）` | 别名，专供 `inference/` 的推断模板对齐名字 |
| `→ 见 …` | 跨课程引用。**知识点只建一个文件，另一个方向只标记**——复制会导致同一件事算两次分 |
| `← A、B` | **前置**：A、B 是会这一条的前提。有向、必须无环，不是「相关」；只用于决定讲解顺序与标出可疑条目。**不做「替代/演进」边**——那是一个知识点的版本变化，拆成两条会让条目膨胀 |

## 粒度约定

- **二级**：一个门类下 1–8 个；37 个学科 + 生活常识的 2 个**时代**（见下）
- **课程**：一个学科下 1–7 门；目前共 78 门
- **知识点**：一门课 8–20 条（少于 8 说明课程切太粗，多于 20 该拆课程）
- **深度封顶四层**（门类→学科→课程→知识点）。需要更细时把一条拆成两条，不加第五层

## 叶节点判据（三条全满足才算一条知识点）

1. **单一可验证**——能用一个问题问出「会不会」。`矩阵运算` 不合格（乘法/求逆/秩是三件）
2. **单次证据能整体点亮**——一次项目或一次讲解能覆盖它
3. **归属唯一**——只属于一个课程；跨课程的用 `→ 见` 标记，不建第二个条目

## 当前覆盖

8 门类有内容 / 38 个二级 / 78 课程 / 493 条。三个门类（农业与生命、医学与健康、
服务业与实务）暂无课程，**不建空目录**——等联网扩展补上再出现。

## 教训：学科骨架只装「能被某门课教的东西」

3.5.0 拆掉 `职业技能.md`（46 条），原因是它从第一天起就是类别错误：
混了思维方式（切面）、人际/工具技能（技能实体）、流程方法（Playbook）、生活常识（知识）。
分流清单见 `design/职业技能分流-mapping.md`。

**装不进任何一门课的东西，不是学科问题**：它是技能（去 `skills/`）、
是流程（去 `templates/playbooks.md`）、还是一种思维方式（去切面）。
