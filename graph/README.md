# 预置学科骨架

> 冷启动时直接铺给用户的知识树起点。**只提供到「课程 → 核心知识点」层级**，不铺到极致——过深的骨架会让用户望而生畏。

## 使用方式

1. 初始化时按用户背景选 2–4 个学科铺开，其余折叠为学科名
2. 所有预置项标记 `origin: preset`，`raw_score = 0`（未触及）
3. 用户可自由增补：新建课程、新建知识点、重命名
4. 骨架更新不覆盖用户已有数据

## 粒度约定

- **课程层**：一个学科下 5–12 门课
- **知识点层**：一门课下列 8–20 个核心知识点，只列真正关键的
- 标记重要度：核心 ⭐⭐ / 一般 ⭐ / 边缘（不标），用于学科聚合加权

## 书写格式

```markdown
- 知识点名 ⭐⭐〔档位〕（又称 别名A、别名B）
```

| 记号 | 含义 |
|---|---|
| `⭐⭐` | 核心，重要度 1.0 |
| `⭐` | 一般，重要度 0.6 |
| 不标 | 边缘，重要度 0.3 |
| `〔tooling〕` | 覆盖学科默认衰减档位 |
| `（又称 …）` | **别名**，供推断模板命中 |

### 别名为什么重要

推断模板（`inference/`）由人撰写，命名常与骨架不一致。
例如职业映射写「渲染管线」，骨架里叫「浏览器渲染原理」——
没有别名就会被当成骨架外的新知识点，归到"其他"学科。

加一行别名即可对齐，这是**最低成本的命名治理手段**：

```markdown
- 浏览器渲染原理 ⭐⭐（又称 渲染管线、渲染流程）
```

## 增补规范

用户新增知识点时：
- 尽量挂载到已有课程下，避免学科扁平化
- 新课程需登记，防止同义课程并存（如"数据结构 / 数据结构与算法"）
- 命名与推断模板不一致时，**优先加别名，不要另起一条**
